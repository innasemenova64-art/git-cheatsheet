# 03. Архитектура

## Схема
```
Агбис ──(API/выгрузка, по расписанию)──┐
amoCRM ─(API, после MVP)───────────────┤
                                        ▼
Sipuni ──(webhook звонков)──► Бэкенд (Django) ◄──► PostgreSQL
   ▲                              │
   └──(click-to-call API)─────────┤ WebSocket
                                  ▼
                        Веб-интерфейс менеджера
```

## Стек (предложение)
- Бэкенд: Python, Django (готовые роли и админка), Django Channels для WebSocket.
- БД: PostgreSQL. Фоновые задачи: Celery + Redis (синхронизация, пересчёт метрик).
- Фронтенд: серверные шаблоны + HTMX, без тяжёлого SPA.
- Развёртывание: Docker Compose, Nginx, HTTPS (Let's Encrypt), российский VPS.
- Бэкапы: ежедневный дамп БД на отдельное хранилище, тест восстановления.

## Принципы
- Локальная копия данных из Агбис: карточка не зависит от скорости внешнего API.
- Агбис остаётся источником истины по клиентам и заказам; в обратную сторону на старте не пишем.
- Все ПД хранятся только на серверах в РФ.

## Модель данных (черновик)
- **Client**: id, agbis_id, amo_id, ФИО, адрес, источник, ЦА, ad_consent (bool + дата + источник согласия), do_not_call, created_at.
- **Phone**: client_id, номер в формате E.164, основной.
- **Order**: client_id, agbis_id, дата, сумма, статус.
- **OrderItem**: order_id, категория услуги/вещи, количество, сумма.
- **ClientMetrics** (пересчитываемая): client_id, orders_count, total_sum, avg_check, last_order_at, avg_interval_days, next_expected_at.
- **Call**: sipuni_id, client_id, direction, номер, manager_id, started_at, duration, result, record_url.
- **Segment**: id, название, фильтры (JSON), автор.
- **Campaign**: id, segment_id, название, текст акции/скрипт, статус, период.
- **CampaignTarget**: campaign_id, client_id, статус, менеджер, результат, call_id.
- **User** + роли.
- **AuditLog**: user, действие, объект, время, ip (входы, просмотр, выгрузки).

## Определение ЦА (начальное, уточняется с заказчиком)
Стартовые правила по давности/частоте/сумме (RFM):
- «Новый»: 1 заказ.
- «Постоянный»: 3+ заказа, последний не старше 1,5 интервала периодичности.
- «Спящий»: давность больше 2 интервалов периодичности.
- «VIP»: верхние 10% по сумме.
Дополнительно теги по видам услуг. Пороги настраиваются.
